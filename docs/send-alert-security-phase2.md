# تقرير الإصلاح: تأمين «إرسال تنبيه» (Phase 2)

**الحالة: ✅ منفَّذ ومُختبَر (15/15 اختبارات ناجحة)**

## 1. المشكلة
معالج `profile:sendAlert` على السيرفر كان يفحص تسجيل الدخول فقط — أي عضو اعتيادي
يستطيع إرسال تنبيه بأي رسالة لأي عضو (انتحال صفة الإدارة، إزعاج، بدون سجل تدقيق
والبدون حد للتكرار). الزر ظاهر في قائمة البروفايل لكل الأعضاء (`!isSelf` فقط).

## 2. الحل المنفَّذ

### السيرفر (`server/socket/profileHandlers.ts`)
| الحماية | التفصيل |
|---|---|
| 1. صلاحية | `canRunAdminAction(userId, "alert")` → تتطلب `alert.edit` أو `alert.all` من `role_permissions` |
| 2. حد التكرار | `alertThrottle` — 5 تنبيهات كحد أقصى في الدقيقة لكل مشرف (نافذة منزلقة) |
| 3. الهرمية | منع إرسال تنبيه لرتبة مساوية أو أعلى — معتمدة على `getUserAuthoritativeRank` (الرتبة الموثقة من DB بدل حقل سهل التقادم) وسمح لماك الموقع (`SYSTEM_OWNER_RANK`) |
| 4. التدقيق | `logModerationEvent(eventType: "profile.send_alert")` — من أرسل لمن وما الرسالة (منتهك سابقاً) |
| (خارج الاسم) | الحفاظ على فحوص سابقة: الرسالة مطلوبة، ≤ 500 حرف، منع الإرسال للنفس |

### الخدمة الجديدة (`server/services/alertThrottle.ts`)
محدد نافذة منزلقة قابلة للاختبار (in-memory، خاصة لكل مستخدم) مع دالة مصنع
`createAlertThrottle` لحقن خزنة معزولة في الاختبارات.

### المشترك (`src/lib/profileAdminPermissions.ts`)
إضافة `alert → "alert"` إلى `PROFILE_ADMIN_ACTION_PERMISSION` — فتستخدمها
الواجهة والسيرفر لها خريطة واحدة (مثل باقي الإجراءات).

### الواجهة (`src/components/profile/ProfileActions.tsx`)
- الزر «إرسال تنبيه» لم يعد ظاهراً إلا لـ `isAdmin` **و** مالك `alert.edit/all`
  (كان ظاهراً لكل عضو).
- لا حاجة لتعديل `AlertSenderPopup` — يفتح فقط من الزر المتحاط.

### ما يظل يعمل بلا تغيير
التنبيه يبُث عبر غارقة العضو `user:<id>` كما هو، والديالوج للهدف كما هو.

## 3. ملاحظات
- خصام `إرسال تنبيه` في مودال الدردشة (`src/components/chat/ProfileModal.tsx`)

  و`Object.hasOwn` بسبب اعدادات lib) — ليسا من تعديلات هذه المرحلة.
