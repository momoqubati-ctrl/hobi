## المرحلة 1: الأساس

### المهمة 1: إنشاء مخطط تسليم الإعلانات — مكتملة

**المعرّف:** `announcement-delivery-storage`

**الوصف:** إضافة تخزين دائم للإعلانات المعلقة، وتسليماتها للمستلمين، وعدادات الحصة حسب يوم الرياض، ونتائج منع التكرار لمدة 24 ساعة.

**معايير القبول:**
- [x] يعرّف مخطط Drizzle القيود والفهارس وعلاقات الحذف اللازمة لعزل التسليم حسب المستلم وحذف محتوى الإعلان بعد إغلاق آخر تسليم.
- [x] يضيف `ensureAnnouncementDeliverySchema` ترحيلًا إضافيًا قابلًا لإعادة التشغيل، ويُستدعى بعد تجهيز الجداول الأساسية في ملحق قاعدة البيانات.
- [x] تغطي الاختبارات المخطط والترحيل دون تشغيله على قاعدة بيانات حقيقية.

**التحقق:** `npm test`، ثم `npx eslint server/db/schema.ts server/db/migrate.ts server/plugins/database.ts tests/announcementDeliverySchema.test.ts`. لا تُطبق ترحيلات حقيقية.

**الاعتماديات:** لا يوجد.

**الملفات المتوقعة:** `server/db/schema.ts`, `server/db/migrate.ts`, `server/plugins/database.ts`, `tests/announcementDeliverySchema.test.ts`.

**الحجم:** متوسط (4 ملفات).

### المهمة 2: حل سياسة المرسل النشطة — مكتملة

**المعرّف:** `announcement-delivery-policy`

**الوصف:** جمع صلاحيات الأنواع والحد الفعلي من تعيينات الرتب النشطة، مع استثناء مالك النظام المحدد.

**معايير القبول:**
- [x] يجمع صلاحيات الإعلان من الرتب النشطة التي بدأ تعيينها ولم ينتهِ، ويحسب أكبر حد من الرتب التي تمنح أي نوع.
- [x] يرفض الإرسال عند عدم وجود صلاحية للنوع أو عند حد فعال صفر؛ ولا يحسب رتبة لا تمنح أي نوع.
- [x] يمنح مالك النظام الموثق المرتبط برتبة `is_owner` حدًا ثابتًا 10000، ولا يمنح هذا الاستثناء لحسابات أخرى.

**التحقق:** اختبارات سياسة مستقلة للحالات متعددة الرتب، والتواريخ، والحدود 0 و1000، ومالك النظام والحسابات الأخرى؛ ثم `npm test` وESLint للملفات المعدلة.

**الاعتماديات:** `announcement-permission-keys`, `announcement-role-limit-schema`, `announcement-policy-api`.

**الملفات المتوقعة:** `server/services/announcementDeliveryPolicy.ts`, `tests/announcementDeliveryPolicy.test.ts`.

**الحجم:** صغير (ملفان).

### المهمة 3: تحديد جمهور الإعلان المتصل — مكتملة

**المعرّف:** `announcement-delivery-audience`

**الوصف:** حل حسابات المستلمين من حالة الحضور والغرفة والرتب عند لحظة الإرسال.

**معايير القبول:**
- [x] يستهدف `all` و`room` الأعضاء المتصلين غير الضيوف فقط، مع إزالة تكرار الحساب حتى لو ظهر عبر أكثر من socket.
- [x] يستهدف `ranked` من لديهم تعيين واحد على الأقل لرتبة نشطة غير افتراضية؛ الرتبة الافتراضية وحدها لا تكفي.
- [x] يتحقق من وجود الغرفة ويستخدم معرفها canonical وعضوية لحظة الإرسال؛ لا تُنشأ قائمة انتظار لمن كان غير متصل.

**التحقق:** اختبارات للجمهور الفارغ، والضيف، والرتبة الافتراضية/المنتهية، والغرفة، وتكرار sockets، وإدراج المرسل عند انطباق الشروط؛ ثم `npm test` وESLint للملفات المعدلة.

**الاعتماديات:** لا يوجد.

**الملفات المتوقعة:** `server/services/announcementAudience.ts`, `tests/announcementAudience.test.ts`.

**الحجم:** صغير (ملفان).

## المرحلة 2: الإرسال

### المهمة 4: تثبيت الإرسال والحصة ذريًا — مكتملة

**المعرّف:** `announcement-delivery-send-service`

**الوصف:** إنشاء خدمة الإرسال التي تحفظ العملية والحصة والتسليمات ضمن معاملة واحدة، ثم تبث الحدث للمستلمين المستهدفين فقط.

**معايير القبول:**
- [x] يتحقق الخادم من نص غير فارغ بطول لا يتجاوز 1000 وحدة نصية، ومن مفتاح UUID وبصمة الحمولة.
- [x] يمنع القفل الذري تجاوز الحصة اليومية بتوقيت الرياض، ويعيد الإيصال الأصلي للمفتاح المطابق خلال 24 ساعة، ويرفض المفتاح ذي الحمولة المختلفة أو الجاري بالتزامن.
- [x] يقبل الجمهور الفارغ ويستهلك إرسالًا واحدًا؛ أما فشل المعاملة فلا يترك حصة أو إعلانًا جزئيًا.
- [x] تُحفظ التسليمات قبل بث `announcement:created` لكل مستلم عبر قناة المستخدم الخاصة؛ يستخدم الإغلاق لاحقًا حدث إزالة خاصًا، ولا يحدث بث عام.

**التحقق:** اختبارات ذرية الخدمة للحد المتزامن، ونافذة الرياض، وإعادة الطلب، وتعارض المفتاح، والجمهور الفارغ، والتراجع؛ ثم `npm test` وESLint للملفات المعدلة.

**الاعتماديات:** `announcement-delivery-storage`, `announcement-delivery-policy`, `announcement-delivery-audience`.

**الملفات المتوقعة:** `server/services/announcementDelivery.ts`, `tests/announcementDelivery.test.ts`.

**الحجم:** صغير (ملفان).

### المهمة 5: توفير API إرسال الإعلان — مكتملة

**المعرّف:** `announcement-delivery-send-api`

**الوصف:** كشف خدمة الإرسال عبر واجهة HTTP موثقة الجلسة ومتوافقة مع عقد المواصفة.

**معايير القبول:**
- [x] يستخدم المسار `getUserAuthContext`، ويرفض الجلسة غير الصالحة والضيف، ولا يقبل هوية المرسل أو المستلمين من الجسم.
- [x] يتحقق من جسم مميز للأنواع، ومن `roomId` للغرفة فقط، ومن ترويسة `Idempotency-Key` المطلوبة.
- [x] يعيد إيصالًا موحدًا، ويربط أخطاء التفويض والغرفة والتحقق والتعارض والحصة برموز HTTP المتفق عليها، دون كشف أخطاء داخلية.

**التحقق:** اختبارات المسار للمصادقة والتحقق وإعادة الطلب ورموز الأخطاء، ثم `npm test` و`npm run build` وESLint للملفات المعدلة.

**الاعتماديات:** `announcement-delivery-send-service`.

**الملفات المتوقعة:** `server/routes/api/announcements/index.post.ts`, `tests/announcementSendApi.test.ts`.

**الحجم:** صغير (ملفان).

### نقطة تحقق: الإرسال

- [x] يمكن إرسال إعلان مصرح به مع إيصال ثابت.
- [x] لا يؤدي تجاوز الحصة أو إعادة الطلب إلى إنشاء إرسال إضافي.
- [x] لا يتلقى أي socket خارج جمهور الإعلان حدث الإضافة.

## المرحلة 3: الاسترجاع والإغلاق

### المهمة 6: استرجاع وإغلاق الإعلانات المعلقة — مكتملة

**المعرّف:** `announcement-delivery-pending-api`

**الوصف:** إضافة API لاسترجاع قائمة المستلم المعلقة بعد تحديث الصفحة وإغلاق عنصر منفرد بشكل دائم.

**معايير القبول:**
- [x] يعيد `GET /api/announcements` قائمة مرتبة بعلامة cursor، تخص الحساب الموثق فقط.
- [x] يغلق `DELETE /api/announcements/:id` تسليم المستخدم وحده؛ العملية idempotent ولا تكشف وجود إعلان يخص حسابًا آخر.
- [x] يزامن الإغلاق عبر اتصالات الحساب، ويحذف نص الإعلان بعد إغلاق آخر مستلم دون حذف سجلات الحصة المطلوبة.

**التحقق:** اختبارات pagination والعزل بين الحسابات والإغلاق المتكرر وحذف المحتوى ومزامنة الحدث؛ ثم `npm test` و`npm run build` وESLint للملفات المعدلة.

**الاعتماديات:** `announcement-delivery-storage`, `announcement-delivery-send-service`.

**الملفات المتوقعة:** `server/routes/api/announcements/index.get.ts`, `server/routes/api/announcements/[id].delete.ts`, `server/services/announcementDelivery.ts`, `tests/announcementPendingApi.test.ts`.

**الحجم:** متوسط (4 ملفات).

### نقطة تحقق: اكتمال وحدة التسليم

- [x] تنجح اختبارات المشروع والبناء وESLint للملفات الجديدة/الخاصة بوحدة التسليم دون أخطاء سببها هذه الوحدة.
- [x] تغطي الاختبارات الإرسال والاستهداف والحصة ومنع التكرار والبث الخاص والاسترجاع والإغلاق.
- [x] لا تُطبق أي ترحيلات على قاعدة بيانات حقيقية.

## حدود الوحدة

- هذه القائمة لا تنفذ زر الإرسال أو نموذج المستخدم أو واجهة شريط الإعلان؛ ستغطيها مواصفة `announcement-experience` بعد إكمال التسليم.
- تعذر فحص واجهة إعداد الرتب مرئيًا في الوحدة السابقة بسبب شهادة HTTPS المحلية؛ لم تُجرَ تغييرات على شهادة النظام أو إعدادات المتصفح.
