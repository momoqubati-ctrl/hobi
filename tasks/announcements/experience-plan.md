# خطة التنفيذ: تجربة الإعلانات (`announcement-experience`)

**الحالة:** معتمدة  
**المواصفة المعتمدة:** [SPEC-announcement-experience.md](../../SPEC-announcement-experience.md)  
**خريطة القدرات:** [CAPABILITY-MAP-announcements.md](../../CAPABILITY-MAP-announcements.md)  
**قائمة المهام:** [experience-todo.md](./experience-todo.md)
**النطاق:** تجربة المستخدم فقط؛ لا تغييرات على قاعدة البيانات أو واجهات التسليم المعتمدة.

## نظرة عامة

إضافة زر إرسال مشروط بالصلاحيات في إعدادات المستخدم، ونافذة إرسال متوافقة مع أنواع الإعلان والغرف، ثم واجهة عامة داخل Dashboard تستعيد إعلانات الحساب المعلقة وتعرضها بالتتابع حتى يغلق المستخدم كل إعلان يدويًا.

## القرارات المعمارية

- فصل أنواع بيانات الواجهة ودوال طلب HTTP في `src/lib/announcements.ts`، وعدم استيراد خدمات الخادم أو مخطط قاعدة البيانات إلى حزمة المتصفح.
- اشتقاق الأنواع المعروضة من `useRealtimeStore.userPermissions` ومفاتيح `announcement_*`; لا يثق التنفيذ الخادمي بأي حالة صلاحية من الواجهة.
- استخدام قائمة الغرف الموجودة في `useRealtimeStore.rooms`، وتمرير معرف الغرفة المعروض إلى API؛ يتحقق الخادم من المعرف ويعيده canonical.
- إبقاء حالة نافذة الإرسال محلية في الإعدادات، وحالة قائمة الاستلام في مكوّن موصول مرة واحدة بمستوى Dashboard حتى لا تختفي بتغيير التبويب.
- تسجيل مستمعي Socket.IO قبل تحميل القائمة، ودمج الاستجابة والأحداث حسب `id`، مع مزامنة `announcement:dismissed` وإعادة تحميل القائمة عند الاتصال/إعادة الاتصال.
- إظهار عنصر واحد في كل مرة بترتيب FIFO، واستخدام `DELETE` قبل إسقاط العنصر محليًا؛ لا مؤقت ولا إغلاق عند النقر خارج الشريط.
- عدم طلب قائمة الإعلانات لجلسات الزوار، مع إعادة تحميلها عند دخول عضو أو تحديث دوره.
- إنشاء `crypto.randomUUID()` لكل إرسال جديد، والاحتفاظ بالمفتاح نفسه فقط لمحاولة إعادة إرسال الطلب ذاته.
- عدم إضافة مكتبات جديدة؛ استخدام مكونات التصميم الحالية، وإشعارات المشروع، واختبارات `node:test`/`jiti`.

## مخطط الاعتماد

```text
عقد وأنواع العميل ودوال API
          ├──> نافذة الإرسال داخل الإعدادات ──> POST /api/announcements
          └──> قائمة المعلّقات ومزامنة Socket.IO
                       └──> شريط FIFO وإغلاق X ──> GET / DELETE /api/announcements
```

## مراحل التنفيذ ونقاط التحقق

### المرحلة 1: عقد العميل والإرسال من الإعدادات

- تعريف أنواع الإعلان والإيصال والعناصر المعلقة للمتصفح ودوال API ذات رسائل أخطاء آمنة.
- إضافة زر يظهر عند امتلاك صلاحية نوع فعالة واحدة على الأقل، ونافذة ترسل نوعًا واحدًا مسموحًا فقط.
- استخدام قائمة الغرف الحالية عند اختيار `room`، وإظهار حدود النص وحالات الإرسال والنجاح والفشل.
- اختبار دوال اختيار الأنواع والتحقق من الجسم والاستجابات، ثم مراجعة وصول زر الإعدادات والنافذة بلوحة المفاتيح.

### نقطة تحقق: الإرسال

- لا يظهر زر لعضو بلا صلاحية، ولا يستطيع العميل اختيار نوع ممنوع بحسب الحالة الحالية.
- لا تقبل الواجهة نصًا فارغًا أو أطول من 1000 وحدة نصية؛ ترسل UUID وتعرض نتيجة API.
- البناء والاختبارات وESLint للملفات المعدلة ينجحون.

### المرحلة 2: استقبال واستعادة الإعلانات

- تركيب مدير قائمة الإعلانات في `Dashboard` خارج محتوى التبويبات.
- تحميل الصفحات من GET، وربط `announcement:created` و`announcement:dismissed` من socket المستخدم.
- إزالة التكرار حسب `id` والتعامل مع وصول الحدث أثناء تحميل القائمة أو الإغلاق.
- اختبار دمج الأحداث والصفحات، والترتيب، ومنع التكرار، وتجاهل الإعلانات المغلقة، ودورات cursor.

### نقطة تحقق: التزامن والاستعادة

- يظهر الإعلان الوارد فورًا، ويظهر الإعلان المحفوظ بعد إعادة التحميل أو إعادة الاتصال.
- لا يُكرر العنصر عند اجتماع حدث Socket.IO مع نتيجة GET أو عند وجود عدة اتصالات.
- إغلاقه من اتصال يزيله من القائمة بعد الحدث، ولا يعيد GET عنصرًا مغلقًا.

### المرحلة 3: الشريط ومراجعة التجربة

- بناء شريط RTL ثابت ومتجاوب أعلى Dashboard يعرض النوع والمرسل وصورته والنص العادي وزر X.
- عرض عنصر واحد فقط بالتتابع؛ لا يختفي بسبب الوقت أو النقر خارج الشريط أو تغيير التبويب.
- مراجعة حالات التحميل والفراغ والصورة المفقودة والخطأ، وإمكانية الوصول ولوحة المفاتيح.
- اختبار يدوي في المتصفح على المقاسات المتاحة، ثم تشغيل الاختبارات والبناء وESLint النهائي.

## المخاطر والتخفيف

| الخطر | الأثر | التخفيف |
|---|---|---|
| يصل `announcement:created` بالتزامن مع جلب الصفحات | تكرار عنصر أو فقدانه | تسجيل الأحداث قبل GET، ودمج العناصر حسب المعرف، واختبار السباق |
| يتغير تبويب Dashboard أو تنتهي صلاحية الجلسة | انقطاع العرض أو بقاء مستمعات مكررة | إبقاء المكوّن في الجذر، وتنظيف المستمعات عند unmount، واحترام دورة اتصال socket |
| قائمة الغرف قديمة أو معرفها slug | رفض الإرسال أو اختيار غرفة خطأ | استخدام معرفات المتجر الحالية، ومعالجة أخطاء 404 بوضوح؛ الخادم يحسم المعرف canonical |
| لا تتوفر جلسة مستخدم مخول لاختبار المتصفح | نقص التحقق التفاعلي الكامل | إكمال الاختبارات الآلية والبناء، وتسجيل الجزء الذي يتعذر فحصه دون اختلاق نجاح مرئي |
