# خطة التنفيذ: إدارة مزوّد الصوت (`provider-admin`)

**الحالة:** معتمدة؛ التنفيذ جارٍ
**المواصفة المعتمدة:** [SPEC-provider-admin.md](../SPEC-provider-admin.md)
**خريطة القدرات:** [CAPABILITY-MAP.md](../CAPABILITY-MAP.md)

## نظرة عامة

تنفّذ هذه الخطة وحدة إدارة المزود فقط: تشفير بيانات LiveKit وتخزين إعدادات متعددة، واجهات API محمية بالصلاحيات، ثم ربطها بتبويب إدارة مزود الصوت. لا تنفّذ فحوصات الصحة والتحويل التلقائي أو دمج LiveKit في واجهة الصوت؛ فهما وحدتان لاحقتان تتطلبان مواصفات معتمدة.

## القرارات المعمارية

- تخزين حسابات LiveKit منفصلة عن الاختيار المطلوب؛ الاختيار المحفوظ لا يعني أن المزود أصبح نشطاً فعلياً. حالة النشاط والتحويل مسؤولية `provider-orchestration`.
- استخدام PostgreSQL مع تغييرات إضافية متوافقة مع قاعدة البيانات الحالية، وبنية تشفير تحمل nonce وauthentication tag. لا تُخزن أسرار بصيغة واضحة.
- قراءة المفتاح من متغير `VOICE_PROVIDER_ENCRYPTION_KEY` بترميز Base64 لمفتاح عشوائي بطول 32 بايت. في التطوير يوضع في `.env` المحلي المستثنى من Git؛ وفي الإنتاج يحقن من بيئة الخادم أو ملف `.env` محمي خارج المستودع.
- استخدام صلاحيات المشروع القائمة: `admin_micprovidercp.read` للقراءة، و`micprovideredit.edit` للتغيير، و`micprovideredit.delete` للحذف. يظل التحقق الخادمي إلزامياً.
- لا تُضاف حزمة تشفير؛ استخدام `node:crypto` المدمج. لا يتصل الاختبار بخدمة LiveKit حقيقية.
- لا تُطبّق أي ترحيلات على قاعدة فعلية أثناء التطوير أو التحقق؛ اختبار الترحيل يكون على قاعدة اختبار معزولة.

## مخطط الاعتماد

```text
تشفير الأسرار
      │
      ▼
تخزين الحسابات والاختيار المطلوب + الترحيل
      │
      ├── واجهات API لإدارة الحسابات
      │
      └── واجهة API لحفظ الاختيار
                 │
                 ▼
      واجهة تبويب مزود الصوت
                 │
                 ▼
      تحقق أمني وتكامل نهائي
```

## المهام

### المرحلة 1: الأساس والتخزين

- [x] المهمة `voice-provider-encryption`: إنشاء خدمة تشفير الأسرار واختبارها.

### نقطة تحقق: الأساس

- [ ] اختبارات التشفير والتخزين تمر، وتشمل المفتاح المفقود/غير الصحيح وفشل فك التشفير.
- [ ] الترحيل الإضافي يعمل على قاعدة اختبار معزولة ولا يغيّر بيانات المزود القديم أو بيانات غير مرتبطة.
- [ ] موافقة المستخدم على تعديل مخطط قاعدة البيانات حاصلة قبل بدء المهمة `voice-provider-storage`.

### المرحلة 2: واجهات الإدارة

- [ ] المهمة `voice-provider-account-api`: قراءة وإضافة وتعديل وحذف حسابات LiveKit مع الصلاحيات والتدقيق.
- [ ] المهمة `voice-provider-selection-api`: حفظ اختيار WebRTC أو حساب LiveKit والتحقق من التعارضات.

### نقطة تحقق: واجهات API

- [ ] اختبارات المصادقة والصلاحيات والمدخلات والاستجابات تغطي كل عملية.
- [ ] لا يظهر مفتاح أو سر أو نص مشفر في أي استجابة أو سجل أو رسالة خطأ.
- [ ] الحساب المحدد لا يُحذف، واختيار LiveKit لا يقبل حساباً مفقوداً أو سراً غير قابل للفك.

### المرحلة 3: واجهة الإدارة والتحقق

- [ ] المهمة `voice-provider-final-verification`: التحقق النهائي وتوثيق متطلبات إعداد المفتاح والتشغيل.

### نقطة تحقق: الإكمال

- [ ] يستطيع المسؤول المصرح له إدارة الحسابات والاختيار، بينما ترفض API أي محاولة بلا الصلاحية.
- [ ] WebRTC يظل متاحاً عند غياب مفتاح التشفير أو فساد إعداد LiveKit.

- [ ] يُراجع السلوك في المتصفح دون حساب LiveKit فعلي أو أسرار حقيقية.
- [ ] موافقة المستخدم على الخطة حاصلة قبل بدء التنفيذ.

## تفاصيل المهام

### المهمة `voice-provider-encryption`: إنشاء خدمة تشفير الأسرار واختبارها

**الوصف:** بناء خدمة خادمية صغيرة تستخدم `node:crypto` وAES-256-GCM، تقرأ مفتاح البيئة بصيغة Base64 وتتحقق من طوله، وتقدم تشفيراً وفك تشفير typed مع رفض واضح للإعداد المفقود أو البيانات المتلاعب بها.

**معايير القبول:**
- [ ] لا يوجد fallback إلى قيمة ثابتة أو تخزين plaintext.
- [ ] فك التشفير يعيد النص الأصلي، ورفض مفتاح غير صحيح أو ciphertext/tag معدل.
- [ ] لا تتضمن رسائل الخطأ أو السجلات السر أو محتوى ciphertext.

**التحقق:** اكتب الاختبارات أولاً ثم شغّل `npm test` و`npm run lint -- server/services/voiceProviderEncryption.ts tests/voiceProviderEncryption.test.ts`.

**الاعتماديات:** لا يوجد.
**الملفات المتوقعة:**
- `server/services/voiceProviderEncryption.ts`
- `tests/voiceProviderEncryption.test.ts`
- `.env.example`

**الحجم:** متوسط.

### المهمة `voice-provider-storage`: حفظ الحسابات والاختيار المطلوب

**الوصف:** إضافة نماذج بيانات حسابات LiveKit والاختيار المطلوب، ومخزن خادمي يشفّر الأسرار قبل الكتابة ويعيد DTO عاماً فقط، مع ترحيل إضافي قابل لإعادة التشغيل بأمان.

**معايير القبول:**
- [ ] يدعم التخزين أكثر من حساب ويحتفظ بالاختيار المطلوب منفصلاً.
- [ ] لا تُخزن مفاتيح LiveKit كنص صريح؛ لا يعيد المخزن الأسرار أو ciphertext إلى المستهلكين.
- [ ] الترحيل متوافق مع البيانات الموجودة ويُختبر على قاعدة بيانات اختبار فقط.

**التحقق:** اختبارات خدمة/تخزين، `npm run db:verify`، وتشغيل `npm run db:migrate` على قاعدة اختبار معزولة فقط.

**الاعتماديات:** `voice-provider-encryption`.
**بوابة موافقة:** تتطلب المهمة موافقة المستخدم قبل أي تعديل للمخطط أو ترحيل قاعدة البيانات.
**الملفات المتوقعة:**
- `server/db/schema.ts`
- `server/db/migrate.ts`
- `server/services/voiceProviderStore.ts`
- `tests/voiceProviderStore.test.ts`

**الحجم:** متوسط.

### المهمة `voice-provider-account-api`: إدارة حسابات LiveKit عبر API

**الوصف:** تنفيذ القراءة والإنشاء/التعديل والحذف، وتطبيق صلاحيات المسؤول الخادمية، والتحقق من رابط LiveKit والحقول، وتسجيل التدقيق دون بيانات اعتماد.

**معايير القبول:**
- [ ] تتطلب القراءة `admin_micprovidercp.read`، والتغيير `micprovideredit.edit`، والحذف `micprovideredit.delete`.
- [ ] لا تُعاد الأسرار في GET أو PUT، والسر المحذوف من حمولة التعديل يبقى محفوظاً دون كشفه.
- [ ] يُرفض حذف الحساب المحدد ويعاد تعارض مفهوم؛ وتستخدم جميع استعلامات DB معاملات.

**التحقق:** اختبارات API لكل حالة مصادقة وصلاحية وإدخال/تعارض، ثم `npm test` و`npm run lint -- <API file paths>`.

### المهمة `voice-provider-selection-api`: حفظ المزود والحساب المطلوب

- [ ] يعيد حالة الاختيار المطلوب بوضوح ولا يدّعي أن المزود أصبح نشطاً فعلياً.

**التحقق:** اختبارات المسار لحالات النجاح والفشل والتزامن، ثم `npm test`.

**الملفات المتوقعة:**

### المهمة `voice-provider-admin-ui`: إدارة المزود من لوحة التحكم

**الوصف:** استبدال العرض العام الحالي في تبويب `micprovidercp` بواجهة عربية/إنجليزية متوافقة مع نمط لوحة الإدارة لإدارة الحسابات والاختيار. تُرسل الأسرار فقط عند إدخالها، ولا يعاد وضعها في حالة الواجهة بعد الحفظ.

**معايير القبول:**
- [ ] تعرض الاختيار المطلوب والحسابات المحفوظة دون قيم سرية.
- [ ] تدعم إضافة/تعديل/حذف الحساب واختيار WebRTC أو حساب LiveKit، مع معالجة أخطاء الخادم.
- [ ] توضح أن الإعداد المطلوب لا يعني أن المزود نشط فعلياً قبل اكتمال وحدة التنسيق.

**التحقق:** بناء التطبيق، فحص lint، ومراجعة التفاعل في متصفح محلي؛ لا تُدخل مفاتيح فعلية ولا تتصل بخادم LiveKit.

**الاعتماديات:** `voice-provider-account-api`, `voice-provider-selection-api`.

**الحجم:** متوسط.

## المخاطر والتخفيف

| الخطر | الأثر | التخفيف |
|---|---|---|
| تغيير المفتاح أو فقده | يتعذر فك أسرار الحسابات المخزنة | حفظ المفتاح في مدير أسرار/نسخة احتياطية آمنة، توثيق ذلك، والفشل المغلق دون إظهار بيانات تالفة. |
| اختلاف المفتاح بين نسخ الخادم | نتائج متباينة وفشل إصدار رموز الصوت | توزيع قيمة واحدة متطابقة على كل النسخ والتحقق منها عند التشغيل. |
| استعمال صلاحية الواجهة فقط | تعديل إعدادات الصوت باستدعاء مباشر للـ API | فرض `guardAdminAction` المناسب على كل مسار واختبار 403. |
| SSRF عبر عنوان خدمة مدخل | وصول الخادم إلى خدمات داخلية | عدم إجراء fetch اختباري من هذه الوحدة؛ التحقق من URL، ووضع قيود الاتصال التفصيلية في مواصفة التنسيق. |
| اختلاف قاعدة التطوير عن الإنتاج | ترحيل غير متوافق أو فقد إعداد | ترحيل إضافي قابل لإعادة التشغيل واختباره في قاعدة معزولة قبل أي بيئة حقيقية. |
| خلط الاختيار المطلوب بالمزود الفعلي | عرض نجاح مضلل أو قطع الصوت قبل جاهزية العملاء | فصل الحالة المطلوبة عن الفعلية حتى تُنفذ وحدة التنسيق. |

## أسئلة مؤجلة

- سياسة السماح بعناوين LiveKit داخل الشبكات الخاصة تُحسم في مواصفة `provider-orchestration` بعد تحديد متطلبات الاستضافة الذاتية.
- إجراء تدوير مفتاح التشفير خارج الإصدار الأول؛ لا يُغير المفتاح بعد حفظ الحسابات إلا بإجراء معتمد أو إعادة إدخال الأسرار.
- لا يُختبر التحويل الفعلي أو الاتصال الصوتي ضمن هذه الخطة.
